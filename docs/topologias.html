Docker Compose

Quando usar: laboratório, demonstração, prova de conceito em uma máquina virtual, desenvolvimento e QA de integração. É a referência para portas e variáveis do produto.

  • O perfil agent inicia o MeshAgent no mesmo ambiente.
  • O perfil ollama atende aos cenários com LLM local, como o cenário 4.
  • O banco de dados pode ser um serviço do Docker Compose ou uma instância externa.

Kubernetes

Quando usar: produção ou pré-produção em cluster, com separação clara entre o plano de controle e os MeshAgents.

Namespace / papel Conteúdo típico
collie-system API, processador, Gateway, banco de dados, mensageria e componentes de Inteligência Artificial e evidências quando disponíveis
collie-agent MeshAgent apenas

No SaaS 1.1 e 1.3 o cliente materializa só o equivalente a collie-agent. Em 1.2 e 1.4, também o Gateway.

O banco de dados no cluster atende a laboratórios e testes básicos, mas não oferece alta disponibilidade. Os manifests do Evidence Processor e dos componentes de Inteligência Artificial para Kubernetes ainda estão em evolução. Para uma implantação Full em produção, valide o empacotamento com a Collie.

Máquinas virtuais

Quando usar: quando o Control Plane, os dados, o Gateway e o MeshAgent precisam de máquinas separadas; quando o MeshAgent usa systemd fora do cluster; ou em uma prova de conceito com Docker Compose.

  • MeshAgent por systemd quando a frota não está no Kubernetes.
  • Banco em VM de dados ou serviço gerenciado.
  • Os mesmos princípios de rede permanecem: o MeshAgent inicia a comunicação e o Gateway HTTPS transporta conteúdo cifrado sem lê-lo.

Ordem recomendada

  1. Feche o cenário SaaS ou Full, com ou sem LLM — ver cenários.
  2. Escolha a topologia Laboratório → Docker. Produção em cluster → Kubernetes. Máquinas Linux → máquinas virtuais com systemd.
  3. Aplique pré-requisitos Rede, TLS, cadastro do MeshAgent e política — consulte como instalar.
