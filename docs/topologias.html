Docker Compose

Quando usar: lab, demo, PoC em uma VM, desenvolvimento e QA de integração. Referência de portas e variáveis do produto.

  • Profile agent sobe o MeshAgent no mesmo compose.
  • Profile ollama cobre cenários com LLM local (ex.: 4).
  • Postgres pode ser serviço do compose ou DATABASE_URL externo.

Kubernetes

Quando usar: produção ou pré-produção em cluster. Separação clara entre plano de controle e agents.

Namespace / papel Conteúdo típico
collie-system API, worker, Gateway, Postgres, RabbitMQ (+ AI/Evidence quando empacotados)
collie-agent MeshAgent apenas

No SaaS 1.1 e 1.3 o cliente materializa só o equivalente a collie-agent. Em 1.2 e 1.4, também o Gateway.

Postgres in-cluster serve lab e smoke — não é HA. Manifests de Evidence Processor e AI no Kubernetes ainda evoluem; Full com AI em produção alinhe o empacotamento com a Collie.

Máquinas virtuais

Quando usar: isolamento por host (Control Plane, dados, Gateway, agent); agent em systemd em hosts Linux fora do cluster; ou PoC em uma VM com Compose.

  • Agent via systemd quando a frota não está no Kubernetes.
  • Banco em VM de dados ou serviço gerenciado.
  • Mesmos princípios de rede: agent outbound-only; Gateway HTTPS opaco.

Ordem recomendada

  1. Feche o cenário SaaS ou Full, com ou sem LLM — ver cenários.
  2. Escolha a topologia Lab → Docker. Produção em cluster → Kubernetes. Hosts Linux → VMs/systemd.
  3. Aplique pré-requisitos Rede, TLS, enroll e política — ver como instalar.
