Como instalar

Quatro passos. Sem atalho de compliance.

Escolha onde roda o Control Plane, abra o playbook do cenário, empacote na topologia certa e valide. Rede, identidade e política de LLM vêm antes do primeiro agent.

Fluxo de instalação

  1. Modelo de compra SaaS (Control Plane na Collie) ou Full (stack no seu ambiente). Essa decisão define o footprint.
  2. Playbook do cenário SaaS 1.1–1.4 ou Full 2–4 — LLM, Gateway e o que instalar no cliente. Ver cenários.
  3. Topologia Docker Compose, Kubernetes ou VMs. Ortogonal ao cenário comercial. Ver topologias.
  4. Configuração e validação Rede/TLS, segredos, enroll do agent, política de LLM. Checklist pós-instalação antes de liberar produção.

Pré-requisitos

Comum a todos

  • Cenário comercial escolhido (1.1–1.4 ou 2–4)
  • Topologia escolhida (Docker, Kubernetes ou VMs)
  • Responsável de rede/TLS e de identidade definidos
  • Janela de mudança e acesso ao cluster ou hosts

SaaS (1.x)

  • Tenant Collie provisionado; usuários Cockpit e papéis de aprovação
  • URLs CONTROL_PLANE_URL / GATEWAY_URL (1.1 e 1.3) ou plano de Gateway local (1.2 e 1.4)
  • Egress HTTPS liberado do ambiente do agent
  • Bootstrap token / processo de enroll alinhado
  • Em 1.4: endpoint LLM / GPU / VPC acordado
  • Em 1.3: confirmação de AI blocked no contrato

Full (2–4)

  • Compute e storage para Control Plane, RabbitMQ e Gateway (+ GPU se 4 local)
  • Postgres: container/in-cluster ou instância externa com backup
  • Estratégia de TLS/DNS para UI, API e Gateway
  • Cenário 2: credencial/endpoint LLM Collie + allowlist de egress
  • Cenário 3: confirmação explícita de stack sem AI
  • Cenário 4: provider LLM, segredos e allowlist de política
  • Plano de MeshAgent (namespace Kubernetes vs systemd)

Segurança na instalação

  • Sem exposição pública do RabbitMQ.
  • Segredos fora do Git — env ou secret manager.
  • Edge Redactor habilitado no agent (recomendado).
  • Evidence raw não sobe ao SaaS nem ao Gateway.

MeshAgent é sempre outbound-only. Se o desenho pede inbound no agent, o desenho está errado.

Packaging do MeshAgent

Mesmo protocolo; packaging diferente conforme a topologia:

  • Kubernetes Deployment — namespace collie-agent (não DaemonSet como path padrão)
  • systemd — host ou VM Linux
  • Compose — profile agent

No onboarding Collie (SaaS) ou no bootstrap Full, o Cockpit emite o token de enroll. Sem token válido, o agent não entra na malha.

Validação pós-instalação

Definition of done antes de liberar produção. Adapte URLs (Collie vs local).

Saúde

  • API / Cockpit responde (login OK)
  • Gateway health OK; no Full, também Postgres e RabbitMQ
  • Com AI: Policy + Router healthy; LLM alcançável se aplicável

Agent

  • Enroll concluído; agent online no Cockpit
  • Heartbeat recente; pull no Gateway sem 401/403 em loop

Fluxo operacional

  • Job tipado de smoke (echo ou collect) completa
  • Resultado na timeline do incidente / audit
  • Edge Redactor ativo (campos sensíveis mascarados no upload)

AI

  • Com AI (1.1, 1.2, 1.4, 2, 4): Privacy Gate → approve → Policy → Router → resposta
  • Reject / blocked → sem chamada ao modelo
  • Sem AI (1.3, 3): collect/remediação HITL OK; nenhuma inferência nos logs

Perímetro

  • Sem raw evidence no SaaS nem no Gateway
  • RabbitMQ sem exposição pública

Este guia cobre o quê e o quando. Variáveis de ambiente, manifests e Terraform ficam no onboarding Collie — agende o discovery se for implantar agora.
