O que o OpsMesh é — e o que resolve

Ferramentas de IA pedem ações na infra. O OpsMesh autentica, autoriza, aprova e audita. MeshAgents executam só o permitido — sem entregar o cluster à IA.

Resolve

Governança entre IA e infra

  • Pedido tipado (Cockpit ou clientes MCP) com identidade e FGAC
  • Aprovação humana (HITL) e Privacy Gate antes de caminho de LLM
  • Execução outbound-only via MeshAgent — pull, não inbound
  • Evidência sanitizada na borda; audit trail de ponta a ponta
Não é

Nem IDE, nem shell livre

  • Não substitui Cursor, Claude Code ou Antigravity
  • Não abre acesso inbound ao cluster do cliente
  • Não entrega shell livre nem credencial ampla à IA
  • Não publica raw log no SaaS nem no portal

Como encaixa

Fluxo resumido: pedido → Control Plane → Gateway opaco → MeshAgent no perímetro. Detalhe por camada em como funciona.

Facilidade Privacy Gate: approve/reject só sobre evidência sanitizada — sem raw no browser.

Alerta Evidence raw não sobe ao SaaS nem ao Gateway. Edge Redactor na borda primeiro.

Alerta AI fail-closed: Policy blocked ou Provider fora = sem inferência e sem downgrade.

Dois modelos de implantação

A pergunta que define o footprint: onde roda o Control Plane?

SaaS

Control Plane na Collie

Ver cenários SaaS → Full

Stack no cliente

Cockpit, Control Plane, Postgres, RabbitMQ, Gateway e agents no seu ambiente. LLM conforme o cenário 2, 3 ou 4.

Ver cenários Full →

Princípios que não mudam

  • MeshAgent outbound-only — HTTPS sainte para Gateway e lifecycle no Control Plane. Zero inbound no agent.
  • Gateway opaco — não lê ciphertext; sem Postgres de negócio.
  • Evidence raw não sobe — raw log não vai para o SaaS nem para o Gateway.
  • AI fail-closed — Policy decide; Router só executa; sem downgrade implícito.

Este guia não cobre

  • Arquitetura interna, API contracts e MVP histórico (Google Workspace / onboarding)
  • Dump de variáveis de ambiente, Terraform e runbooks de lab/demo
  • Deploy de ambiente demo Collie
