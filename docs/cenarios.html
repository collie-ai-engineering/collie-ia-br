SaaS — Control Plane na Collie

A Collie opera Cockpit, Control Plane, banco de dados, mensageria, Evidence Processor e os recursos de Inteligência Artificial contratados. No seu ambiente ficam o MeshAgent e, nos cenários 1.2 e 1.4, o Gateway.

1.1

LLM Collie + Gateway Collie

No cliente: MeshAgent LLM: Collie Gateway: Collie

Quando escolher: sua equipe quer Inteligência Artificial gerenciada pela Collie sem operar Gateway, mensageria ou banco de dados. Os MeshAgents podem iniciar conexões HTTPS para os endereços da Collie.

1.2

LLM Collie + Gateway no cliente

No cliente: MeshAgent + Gateway LLM: Collie Gateway: cliente

Quando escolher: sua equipe quer usar a LLM Collie, mas os MeshAgents devem consultar um Gateway dentro da rede do cliente por requisitos de conformidade, latência ou segurança. O cliente opera o Gateway; o plano de controle e os recursos de Inteligência Artificial ficam na Collie.

Implantação prevista. Os pacotes atuais mantêm o Gateway junto ao Control Plane. Até existir um pacote exclusivo para o Gateway, use o cenário 1.2 como referência de arquitetura e valide o desenho com a Collie. Para uma prova de conceito imediata, o cenário suportado é o 1.1.

1.3

MeshAgent para operação sem LLM

No cliente: MeshAgent LLM: nenhuma Política: sem inferência

Quando escolher: a equipe usa o Cockpit para incidentes, coleta de dados e remediação com aprovação humana, mas não quer ou não pode usar uma LLM. É o cenário SaaS sem inferência.

1.4

LLM própria ou de terceiro + Gateway interno

No cliente: MeshAgent + Gateway (± LLM) LLM: própria / terceiro CP: Collie

Quando escolher: dados sensíveis exigem uma LLM interna, como Ollama ou vLLM, ou uma API de terceiro dentro da VPC. O Gateway fica no ambiente do cliente; o Control Plane e o Cockpit permanecem no SaaS da Collie.

Mesma condição técnica do cenário 1.2. A separação entre Gateway e Control Plane faz parte do desenho previsto; os pacotes atuais ainda executam os dois componentes juntos. Para uma prova de conceito imediata, use o cenário 1.1. A implantação do 1.4 exige validar com a Collie a conexão e o endereço da LLM.

Full — todos os componentes no ambiente do cliente

No modelo Full, Cockpit, Control Plane, banco de dados, mensageria, Gateway, MeshAgents e, conforme o cenário, AI Policy, AI Router e LLM são executados no ambiente do cliente.

2

Full com LLM Collie

Componentes: no cliente LLM: Collie (túnel/endpoint)

Quando escolher: sua organização precisa executar todos os componentes no centro de dados ou na nuvem, com governança local, mas prefere usar uma LLM gerenciada pela Collie. A política de rede permite saída controlada apenas para a inferência.

3

Full sem LLM

Componentes: no cliente LLM: nenhuma Política: sem inferência

Quando escolher: sua equipe precisa do OpsMesh completo no ambiente local, com Cockpit, MeshAgents e remediação aprovada por uma pessoa, mas sem conversas ou recomendações geradas por LLM. Não há Ollama nem adaptadores de nuvem.

4

Full com LLM externa ou própria

Componentes: no cliente LLM: Ollama / vLLM / BYO

Quando escolher: sua organização quer a instalação Full e o modelo sob o próprio controle. A política pode restringir a inferência ao ambiente local ou autorizar provedores externos específicos.

Depois do cenário, escolha a topologia: Docker, Kubernetes ou máquinas virtuais. O cenário define quais componentes instalar; a topologia define como executá-los.
